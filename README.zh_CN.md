## 项目概览

ADTY AI 将多家上游大模型服务聚合为统一 API 网关，并在同一套 Web 控制台中闭环管理账户鉴权、模型定价、多通道收款、零透支资金账本、分站经营、团队共享余额、分站员工授权、工单管理、站内公告与通知审计。

- **正式交付**：Web 控制台与 API 服务。
- **数据与缓存**：主业务库与独立日志库统一使用 **PostgreSQL 18.x**，缓存与限流使用 **Redis**。
- **计账基准**：内部采用固定整数额度换算，**1 美元 = 500,000 额度**，避免浮点精度漂移。

## 支持语言与双语体系

产品界面、文档、订单与资金说明、表单、错误提示、站内公告、工单与固定通知模板仅支持简体中文与英文：

- **简体中文（`zh-CN`）**：浏览器偏好为中文时默认启用，正式首页路径为 `/zh-cn`。
- **英文（`en`）**：其他浏览器偏好默认启用，正式首页路径为 `/`（`x-default`）。
- **用户手动切换优先**；固定通知模板在后台维护双语版本。
- **动态翻译**：Root 可在运维设置中配置系统翻译任务，将动态中文内容自动译为英文；翻译失败时保留中文并标明英文未就绪，且不扣减客户、团队或站长余额，也不递归调用本站网关。

## 角色与权限模型

| 角色 | 核心职责与权限边界 |
| --- | --- |
| **Root（超级管理员）** | 全平台配置、渠道与模型管理、支付通道与场景配置、开站/关站、分站等级与提现审核、主站团队创建、普通管理员分权及全量审计。 |
| **普通管理员** | 默认零后台权限；由 Root 按「区域 · 动作」逐项授权并随时收回，无权访问统一返回 `403`。 |
| **分站站长** | 由 Root 开设分站时创建的独立纯管理账号且永久固定（不可更换或移交，不具备消费/API 功能）；管理本站品牌、域名、单一零售倍率、客户、本站团队、本站工单、一级邀请返佣、收益/保证金与员工授权。 |
| **分站员工** | 由站长创建的独立账号，登录后仅进入员工工作区（`/site-staff`）；客服、财务、运营、管理四类角色默认只读，高危操作需显式授权，改权/停用/删除立即失效旧会话。 |
| **团队负责人** | 管理团队共享余额、一次性成员注册链接、独立员工与团队 Key；负责人固定不可更换。 |
| **普通客户** | 注册登录、在线充值与兑换码充值、创建与管理个人 API Key、查看模型价格与个人用量日志、提交与跟进工单；非团队账号不展示任何团队信息。 |

## 核心功能模块

### 1. 多模型统一 API 网关与计费保护

- **全协议接入**：兼容 OpenAI（Chat Completions / Responses）、Claude、Gemini、Embeddings、Rerank、图片、音频、Realtime 及异步任务；支持 JavaScript 任务插件扩展异步任务计费与轮询。
- **流式保活**：所有流式响应在等待首字期间支持发送保活帧，降低长推理被网关或代理中断的风险。
- **零透支预扣与结算**：付费请求先按估算预扣，余额不足直接拒绝且不发往上游；结算时多退少补，少扣差额记入原账户短差额记录与日志，不暂停该账户后续有余额时的付费请求。免费模型同样记录付款账户以便后续违规费用归属。
- **渠道状态与限流**：通过内置定时模型/图片探测与 Uptime Kuma 监控在模型广场（`/pricing`）与渠道状态页（`/model-status`）展示近 24 小时可用率与延迟（无样本明确显示暂无数据，不伪造 100%）；API Key 须显式绑定具体分组，支持用户级与 Key 级 RPM、TPM 与并发限流，Redis 计数不可用时拒绝放行。
- **视图脱敏与模型广场**：客户日志隐藏上游渠道、上游密钥与内部倍率；模型广场（`/pricing`）清晰展示当前站点启用模型的实际售价、计费方式、缓存价与可用分组。

### 2. 账户认证、二次验证与控制台体验

- **本地凭据与安全防护**：账号密码登录，支持邮箱验证与 TOTP（2FA）；连续密码错误触发锁定窗口；注册验证码不向已注册邮箱泄露账户存在性（防邮箱枚举）；不提供 Passkey 或任何第三方 OAuth 登录。
- **分级二次验证**：资金写操作、密钥与通知配置、站长敏感操作按策略触发单次二次验证（支持密码、邮箱验证码、2FA、会话确认与 Root 豁免），授权严格绑定具体操作与目标。
- **控制台可用性**：全站页面标题、卡片标题、表单标签、表头、页签与导航标签均支持直接选中与复制。

### 3. 多通道充值、支付场景与资金账本

- **版本化支付场景**：钱包按服务端授权场景动态展示可用通道与限额，支持全站用户充值（`wallet_topup`）、站长保证金在线充值（`owner_margin_topup`）以及团队充值（`team_topup`，默认继承钱包规则并支持独立配置通道与限额）。
- **易支付多通道（支付宝 / 微信支付）**：后台「计费与支付 → 支付网关 → Epay」页签顶部直接内嵌通道管理（网关地址、商户 ID/密钥、显示名称、限额、优先级与下单测试）；客户侧按启用通道平铺展示按钮，选中通道不可用时提示切换，不静默换通道。
- **BEpusdt USDT 收款**：支持 TRC20、BEP20、Polygon、X Layer 四条链，站内展示收款地址、应付金额与二维码，支持回调验签与主动补查恢复。
- **支付方式充值赠送与兑换码**：充值赠送仅按支付方式比例快照计算（分站可直接为主站已启用的支付方式配置本站赠送比例，无需 Root 按站授权，由收益优先冻结 / 授权保证金补位）；主动发放客户额度统一使用一次性额度兑换码（完整码仅签发时返回一次，支持到期试用赠送自动清零未使用部分）。
- **分层余额与多步人工退款**：钱包区分本金、到期赠金与永久赠金，消费顺序为「本金 → 先到期赠金 → 永久赠金」；人工退款在订单管理中按多步状态机推进（申请、审批、回收本金、处理赠金、冲回佣金、登记线下打款、完结，支持多次部分退款并受 `S + H + U + X + r <= L` 守恒约束），仅回收可退本金并收回赠金（不退现、不扣负），按退本比例自动冲回主站或分站邀请佣金，实际打款在线下完成。
- **全链路追溯**：人工调额强制原因与幂等键，禁止非 Root 调整同级或更高级角色余额；订单、退款、兑换、调额、资金批次与支付异常均支持按权限全链路追溯。

### 4. 分站经营体系

- **结构化开站与前置就绪检查**：仅 Root 可在「分站管理」顶部核对就绪条件（分站总开关、至少一个已启用且配置正数供货折扣的分站等级、平台根域名）后，通过独立「开设分站」弹窗为新站点创建独立站长管理账号并一键开站，支持 `Idempotency-Key` 幂等防重、自动/自定义子域名与开站结果交付页；开站无需额外签署开站协议。
- **域名与独立品牌**：支持子域名、已验证自定义域名、网站与 API 分域、可选 Cloudflare for SaaS 与 AliDNS 自动化、以及站点独立名称、Logo 与公告。
- **基于分站等级的供货定价**：
  - 供货折扣统一由**已启用分站等级**决定（每级必填大于 0 的供货折扣与可选保证金目标，不再设置全局默认系数/下限或旧版月消费分档）。
  - 等级自动升降级**仅考核客户累计净充值本金（扣除退款）**；开站或切回自动模式时立即按当前规则匹配等级并同步保证金要求。
  - 供货价调整实时生效并立即通知站长；站长调整本站单一零售倍率（`1x–10x`）实时生效；分站团队按「分站供货价 × 分站团队倍率（`1.0x–10.0x`）」计费，绝不低于供货价。
- **站长资金与保证金**：站长中心展示收益钱包与保证金钱包（不暴露经营钱包页面，站长账号为纯管理账号且不提供自用充值或消费功能）；可用收益可申请 USDT 收益提现或转入本站保证金钱包；保证金支持 Root 直接补缴、Root 签发保证金充值码（`site_margin`）、站长在线充值（`owner_margin_topup`）与可用收益划转四条补充路径。
- **主站推广与分站一级邀请**：主站用户享有主站推广返佣（成为站长后自动停止主站返佣）；分站客户享有本站独立一级邀请链接（`?site_invite=`）、首单前补绑与 `/referral` 分站专属视图，佣金单独冻结，提现与撤销窗口由该站站长管理；关站后存量分站邀请佣金提现由具备推广读取、审核与打款权限的主站推广财务席位（含 Root）承接审核与打款。
- **关站迁移**：Root 发起关站后，客户与存续团队迁入主站，历史订单、退款、任务与结算保持原财务归属。

### 5. 团队管理与成员隔离

- **独立管理入口**：Root「团队管理」（`/admin-teams`）集中查看全站团队、成员、团队 Key 与共享余额流水、签发团队注册链接与处置资金异常；站长「团队管理」（`/site-owner/teams`）管理本站团队。
- **团队建团与定价**：主站后台创建团队固定归属主站，按「主站实时分组售价 × 团队折扣」计费；分站团队由站长在本站管理，按「分站供货价 × 分站团队倍率（`1.0x–10.0x`）」计费且绝不低于供货价。
- **单团队与非团队隔离**：非团队账号完全隐藏侧边栏「我的团队」入口及全部团队信息并拦截直达 `/my-team`；已登录普通账号不通过邀请码拼团，仅通过一次性注册链接创建独立成员；团队 Key 仅扣共享余额，撤权后不可改扣个人钱包；活跃团队负责人可重置独立员工密码并立即吊销旧会话；负责人退团或关团后共享余额保留且保留负责人只读回显。

### 6. 分站员工工作区

- 站长可创建、改权、停用、改密与删除员工账号；客户停用等敏感权限（如 `customers.disable`）默认关闭且须显式授予。
- 员工严禁查看完整客户 Key、重置客户密码、代客户登录、直接退款、发起客户余额调整或操作站长资金；向客户发放额度统一通过站长签发站点兑换码完成。

### 7. 工单管理、公告通知与 Telegram 通知机器人

- **工单管理**：平台独立入口（`/admin-tickets`）、站长独立入口（`/site-owner/tickets`）、员工工作区（`/site-staff`）与客户独立支持中心（`/support`）共用同一工单数据流；支持队列筛选、真实角标、建单/回复多图批量上传（额度预检、脱敏提示、私有访问与审计删图）、内部备注隔离与指派流转。
- **站内公告与通知**：支持全平台、全分站或单分站范围发布，服务端维护版本化已读回执与严重待办状态。
- **Telegram 通知机器人**：后台「系统设置 → 运营 → Telegram 机器人」通过独立双卡片分别管理「用户机器人」与「管理机器人」（状态标签、`@username`/ID、启用开关、加密 Token、发送测试、可复制 Webhook URL 与一次性密钥），同页完成平台管理机器人绑定。机器人仅推送通知，不提供修改账户、余额、退款或密钥的任何指令。

## 部署指南

### 生产部署

完整生产部署、Nginx/TLS、Cloudflare 与备份/回滚流程见 [docs/adty/deploy.md](./docs/adty/deploy.md)。

生产编排文件位于 [`deploy/adty/docker-compose.yml`](./deploy/adty/docker-compose.yml)，在 `.env` 中通过 `ADTY_IMAGE` 固定不可变镜像标签（升级与回滚仅改该标签）：

```text
ADTY_IMAGE=ghcr.io/adtyai1995/adtyai-api:sha-1a2b3c4
```

上线前请核对：镜像摘要、PostgreSQL 18、Redis、支付回调地址、会话密钥与定期备份；切勿将生产密钥提交进仓库。

### 本地编排（仅开发与联调）

仓库根目录的 [`docker-compose.yml`](./docker-compose.yml) 用于本地构建联调（非生产部署）。设置 `POSTGRES_PASSWORD` 与 `REDIS_PASSWORD` 后运行：

```bash
docker compose up -d --build
```

启动后访问 `http://localhost:3000`。本地编排构建 `adtyai-api:local`、仅监听本机 `3000` 端口；默认 Compose 项目名为 `adtyai-api`，服务默认使用中国标准时间 `Asia/Shanghai`。如从旧项目名升级，请使用 `docker compose -p <原项目名>` 沿用既有 PostgreSQL 数据卷。
