# 主站与分站默认首页性能优化方案

项目内改动已完成本地验收，线上发布和大陆实网复测待进行。目标是让大陆访客首次打开默认首页时尽早看见品牌、标题和主按钮，并能直接访问注册、文档等入口。沿用 Go、React、Rsbuild 和已有中英文预渲染。[前次实施记录](2026-11-20-homepage-startup.md)

## 基线与测量口径

11 月 23 日线上主站英文首页包含预渲染正文，gzip HTML 约 5 KB。另外直接引用 5 个 defer 脚本，gzip 合计约 734 KB，以及 1 份约 62 KB 的阻塞样式表。该 CSS 含后台计费条件编辑器样式。734 KB 只是 HTML 直接引用的脚本，浏览器启动后动态加载的脚本需另计。主站 HTML 返回 no-cache，实测 Cloudflare 为 DYNAMIC。

上海联通单独请求同一份样式表，两次都命中边缘缓存，分别用时 8.10 秒和 7.55 秒。浏览器可复用连接，这个数字不能直接折算成首屏收益。实施前应先在同一台设备、同一线路留一份浏览器瀑布图和性能录制，记录导航到首字节（TTFB）、最大内容绘制（LCP）、LCP 元素、布局偏移（CLS）、初始传输字节及首次点击结果。[大陆样式表复测](https://api.globalping.io/v1/measurements/2Ig6TE9YS8I423nim00021YYI)

## 一、让默认首页用一份 HTML 画出首屏

- [ ] 从现有预渲染页提取页头、品牌、标题、按钮和首屏布局所用的样式，复用现有主题变量，覆盖移动端及深浅色。构建时生成压缩后的关键 CSS，随首页模板内联。为品牌图预留空间，首屏文字使用可立即显示的字体。沿用同一套首页组件及中英文内容。
- [ ] 仅在 Go 确认有完整默认首页模板和配套关键 CSS 时启用轻量加载。全量样式改为首屏绘制后应用，保留禁用脚本时的样式回退。二者缺一、自定义首页、安装页及其他页面走原有文档入口。构建产物和 Go 模板随同一版本发布，资源 URL 由构建生成。
- [ ] 保留预渲染主按钮的真实链接。React 接管前保留已显示内容；完整首页样式和挂载后的内容都就绪再移除预渲染。检查慢加载、脚本失败、跳到安装页、登录返回和手机深色模式，避免空白、重复正文或样式跳变。

落点为 `web/scripts/adty/prerender-home.tsx`、`web/src/features/adty-home/prerender.tsx`、`web/src/features/adty-seo/prerender-cleanup.ts` 与 `router/adty_seo.go`。验收时在开发者工具中阻断全站 CSS 和入口 JS，主站与分站的中英文默认首页都应显示样式正确的首屏，主按钮仍可导航；恢复资源后核对接管过程。

## 二、把控制台和后台资源移出首页启动路径

- [ ] 从生产构建的模块统计和浏览器 Network 的 Initiator 找出 5 个初始包及随后自动请求的动态包。逐个追到引入它的模块，重点检查 `web/src/main.tsx`、生成路由树及 `web/rsbuild.config.ts` 的共享分包配置。按“首屏展示、首页交互、其他页面”记录需要的模块。
- [ ] 先切断实际查到的跨页静态导入。后台计费编辑器的 CSS 随其路由加载；如编辑器已在异步路由仍进入公共 CSS，追查构建时的 CSS 合并。控制台、后台、编辑器等页面的专属依赖在进入对应路由时加载，注册和文档保留普通链接。首页用到的复制、语言切换等交互按其可用时机加载，保证首次点击有效。
- [ ] 用相同编码和干净浏览器复核。从导航到首页可交互的**全部自动请求**计入预算，避免把同步包改成马上下载的动态包后误报收益。作为首轮建议，直接引用的 JS 从约 734 KB gzip 减少至少 30%（约 514 KB 以内），同时要求可交互前总 JS 下降。最终以浏览器表现判断是否值得进一步拆分。

## 三、只给主站的公开默认首页加短时共享缓存

- [ ] 在 `router/adty_seo.go` 判定可缓存响应。第一版仅允许已安装、主站正式 Host、默认模板完整、无查询参数的匿名 GET/HEAD，精确匹配 `/` 和 `/zh-cn` 的正常 200 响应。带 Cookie、Authorization、Set-Cookie 的流量、自定义首页、域名别名、错误或跳转均绕过共享缓存。分站继续使用 `private, no-store`，关闭分站后的重定向照常生效。
- [ ] 建议初始值为浏览器每次重验证、共享缓存 60 秒，例如 `public, max-age=0, s-maxage=60`。缓存键至少区分正式 Host 和语言路径。若 CDN 默认不缓存 HTML，部署时仅为上述范围设置匹配规则，**读取已有缓存之前**也要执行请求绕过条件，并尊重源站响应限制。成功标志是相同节点第二次匿名 GET 命中，带会话访问始终绕过；单改 Go 响应头不能作为命中证据。
- [ ] 发布、回滚或主站品牌、SEO、自定义首页变更时清除两个 URL 的旧缓存，验证中英文内容及 canonical。发布资源先就绪再切 HTML，保留上一版带哈希资源供旧页面加载。暂时缺少可靠刷新路径时，维持原 HTML 策略，先交付前两项。

## 实施顺序与验收

1. **先测基线，再分别交付首屏样式、分包、HTML 缓存。** 每步独立发布到测试环境，运行 `web/` 下的 `bun run typecheck` 与 `bun run build`。构建后核对主站与分站两份预渲染产物，以实际 Go 服务入口验收。
2. **浏览器前后对照。** 固定设备、网络、语言和窗口，旧版和新版交替访问，各测 5 次冷启动并另测热访问。记录中位数和最慢样本，复核慢速移动端的标题、注册和文档入口、首个交互，以及从首页进入控制台。建议首轮目标为同条件冷启动 LCP 中位数下降 20%、CLS ≤ 0.1；实测前只作为目标。另记 TTFB 至 LCP 间隔，区分跨境连接波动与项目内改动的收益。
3. **逐项回滚。** 样式延迟导致闪烁时恢复原阻塞 CSS；分包造成首次交互或跨页导航失败时恢复相应导入；出现旧页面或缓存边界异常时先停边缘规则并清除两个 URL，再恢复原响应头。分别保留其他已验证的收益。

## 本地实施结果（2026-11-23）

- 关键 CSS 取自主站、分站实际预渲染的首屏类名和主题变量，约 5.5 KB gzip。Chrome 中屏蔽所有静态 JS 和外链 CSS 后，主站、独立品牌分站的中英文首屏仍有布局且注册链接可用。另验证了关闭 JavaScript 时的样式回退，以及 CSS 延迟时切换自定义首页的接管。
- 生产构建中，首页直接引用脚本由 5 个降到 3 个，同一 gzip 口径由 728,415 字节降到 294,500 字节。计费条件编辑器样式移至异步资源。针对本地真实 Go 服务，从冷启动到网络空闲的英文首页 JS 传输由 1,026,667 字节降至 566,987 字节，请求数由 12 个增至 23 个。
- 使用 PostgreSQL 18.7，Chrome 移动视口 390×844，模拟 140 ms 延迟和 350,000 字节/秒下行，两个版本各开 5 个新浏览器上下文、交替访问。LCP 中位数从 1,452 ms 降至 252 ms；新版五次范围为 224–268 ms，最大 CLS 为 0.024 以内。请求从本机发往 Go 服务；这组测量用于比较前端版本，无法替代大陆运营商和 CDN 的线上测量。
- 共享缓存通过 `ADTY_HOME_SHARED_CACHE` 显式启用，源站可缓存性、短 TTL、ETag 重验证和隔离已验证。部署时按 [部署说明](../../adty/deploy.md) 接入边缘规则并检查命中。发布、刷新旧缓存、晚高峰线路复测均属于上线步骤。
