# 账号安全与访问令牌

在控制台安全中心 [https://www.adtyai.com/security](https://www.adtyai.com/security) 中，你可以集中管理双因素认证、登录会话以及个人访问令牌（PAT）。

## 双因素认证（2FA）

开启基于 TOTP 的双因素认证后，即使登录密码意外泄露，攻击者也无法直接登录控制台查看 API Key 或变更安全配置。

### 开启步骤

1. 打开 [https://www.adtyai.com/security](https://www.adtyai.com/security)。
2. 点击**开启双因素认证（2FA）**，使用任意标准 TOTP 身份验证器（如 1Password、Bitwarden、Google Authenticator、Authy 等）扫描二维码。
3. 输入验证器生成的 6 位动态验证码完成绑定。
4. **立即妥善保存离线恢复码**：建议保存在密码管理器或离线安全介质中。

::: warning 离线恢复码使用须知
每组离线恢复码仅可使用一次，用于在更换或遗失手机验证器时找回账号。重新生成恢复码会立即令旧恢复码全部失效。切勿将恢复码明文保存在公开代码仓库或聊天记录中。
:::

## 敏感操作二次验证（Step-Up Verification）

即使账号当前已处于登录状态，执行以下高危敏感操作时，系统仍会要求完成一次短时有效的**二次验证**（通过 2FA 动态码或账号安全验证方式）：

- 查看已有 API Key 的完整明文密钥
- 修改账号登录密码
- 调整或关闭 2FA 安全设置
- 创建、修改或吊销个人访问令牌（PAT）
- 注销当前账号

该机制可有效防止浏览器临时未锁屏时造成密钥泄露或账号安全风险。

## 活跃会话查看与强制注销

在 [https://www.adtyai.com/security](https://www.adtyai.com/security) 的**活跃会话**列表中，你可以实时审查所有已登录设备：

- 查看每个会话的登录 IP、设备/浏览器信息、登录时间与最近活跃时间。
- **单设备下线**：发现不再使用的公共设备或陌生登录记录时，可一键撤销对应会话。
- **下线其他全部会话**：修改密码或排查安全风险后，建议立即注销除当前设备外的全部登录态。

## 个人访问令牌（PAT）

**个人访问令牌（Personal Access Token）**用于让自动化脚本、监控面板或桌面辅助工具（例如余额与用量查询插件）安全调用控制台管理接口，而无需暴露你的登录密码或 Cookie。

- **与模型 API Key 职责不同**：PAT 仅用于控制台账户与数据管理接口，**不能**用于调用 `/v1/chat/completions` 或 `/v1/messages` 等模型推理接口；模型调用请始终使用 `sk-...` API Key。
- **最小权限作用域（Scope）**：创建 PAT 时仅勾选该脚本真正需要的权限范围（例如仅需查询余额时只授予只读权限）。
- **过期时间与及时吊销**：为 PAT 设置合理有效期，不再使用的令牌应及时在安全页面撤销。

## API Key 安全最佳实践

发放和管理 `sk-...` 模型调用密钥时，建议坚持以下习惯：

- **按项目与环境隔离**：为个人 CLI 工具、本地开发、测试环境、生产服务分别创建独立 API Key，避免单点泄露波及全部业务。
- **设置美元额度上限与有效期**：面向自动化 Agent、临时评测或外包环境发放的 Key，务必配置明确的单 Key 消费上限与到期时间。
- **限制允许模型与 IP 白名单**：当服务端出口 IP 固定或业务只需调用少量特定模型时，在令牌配置中启用模型白名单与 IP 白名单。
- **杜绝明文入库**：通过环境变量、被 `.gitignore` 忽略的 `.env` 文件或专业密钥管理服务注入 Key，绝不提交到 Git 仓库。
- **发现泄露立即轮换**：一旦密钥不小心出现在日志、终端截图或提交历史中，请立刻在控制台禁用或删除旧 Key 并换发新 Key。
